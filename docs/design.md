# 디자인 기준

업무 보드의 화면은 모두 이 문서를 따릅니다. 새 화면, 새 컴포넌트, 기존 화면 손질 모두 해당합니다.
기준을 바꿀 때는 이슈를 먼저 만들고 이 문서와 `web/src/app/globals.css`를 같은 PR에서 고칩니다.
지금 기준은 v3(#48)입니다. 합의 과정과 이전 화면과의 차이는 [design-v3-proposal.md](design-v3-proposal.md)에 있습니다.

## 1. 방향

**목적.** 10명 안팎의 팀이 "누가, 어느 프로젝트에서, 무엇을, 어디까지" 하는지 한눈에 보게 합니다.
매일 여는 사람은 개발자가 중심이지만, 기획, 디자인, 운영 담당도 같은 화면을 봅니다.

**톤: 조용한 작업대.** 개발자가 하루 종일 켜 두는 도구처럼 보입니다. 차가운 회색 바탕 위에 흰 판(카드) 몇 장을 놓고,
그 안의 표와 목록이 주인공입니다. 위계는 **글자 크기, 굵기, 여백**으로 만들고 선은 최소로 씁니다.
판은 테두리 선 대신 옅은 고리(ring)로 바탕과 나뉩니다. 그라디언트, 종이 질감, 장식 그림자를 쓰지 않습니다.

**기억에 남을 한 가지: 주홍 깃발과 거터는 "여기를 보세요"에만 씁니다.**
화면 전체가 회색과 흰색으로 차분하고, 주의가 필요한 곳(긴급, 오래 멈춘 일, 담당자 없음, 리뷰 대기)에만
주홍색 깃발이 나옵니다. 긴급인데 아직 시작 전인 줄에는 코드 diff의 변경 표시처럼 왼쪽에 3px 주홍 거터가 붙습니다.
버튼, 링크, 선택 상태에는 주홍을 쓰지 않습니다. 강조색이 곧 경보색이라 의미가 흐려지지 않습니다.

**한 문장 현황.** 개요 화면 맨 위에는 숫자 묶음 대신 사람이 쓰는 문장 하나를 둡니다.
예: "긴급 2건 중 1건은 아직 시작 전이고, 리뷰를 기다리는 PR이 3건 있습니다."
가장 중요한 사실을 쉬운 한국어로 먼저 말하는 것이 이 제품의 목소리입니다.

**왜 이 방향인가.**

- 매일 쓰는 도구의 문법(표, 거터, 단축키, 고정폭 번호)을 따라야 개발자가 낯설어하지 않습니다.
- 한글 문장은 비례폭(IBM Plex Sans KR)과 넉넉한 줄 간격으로 두어 기획·운영 담당도 편하게 읽습니다.
- 색을 줄이고 주의 색 하나만 남기면 10초 안에 "손봐야 할 곳"이 보입니다.
- 선을 줄이고 간격으로 묶으면 같은 정보가 더 가볍게 읽힙니다.

## 2. 글꼴과 글자 단계

모두 Google Fonts에서 받습니다(`next/font/google`, `--font-plex-kr`, `--font-plex-mono`). 글꼴은 두 가지뿐입니다.

| 역할 | 글꼴 | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| 본문·표제 (sans) | **IBM Plex Sans KR** | 400, 500, 600, 700 | 모든 글자 |
| 고정폭 (mono) | **IBM Plex Mono** | 400, 500, 600 | **ASCII만**: 저장소 이름과 번호(`booking-api #102`), PR 번호, 핵심 숫자, 단축키 |

**Mono는 ASCII에만 씁니다.** Plex Mono에는 한글이 없어 한글이 섞이면 대체 글꼴로 그려지면서 칸이 벌어집니다.
날짜와 경과(`11월 10일`, `1일 전`, `3d ago`)는 Sans로 쓰고 `tabular-nums`로 자리를 맞춥니다. 숫자 하나만 Mono로 감싸는 것은 됩니다.

크기는 언어와 상관없이 같고, **줄 간격은 언어에 따라 다릅니다**(한글은 받침과 획이 세로를 채워 더 넓게).
`<html lang>`이 바뀌면 `:root[lang="en"]`의 값이 적용됩니다. 줄 간격은 px로 고정해 4px 격자에 맞춥니다.

| 단계 (클래스) | 크기 | 줄 간격 ko | 줄 간격 en | 굵기 | 자간 | 쓰는 곳 |
| --- | --- | --- | --- | --- | --- | --- |
| `text-display` | 32px (≤639: 24) | 44px (≤639: 34) | 40px (≤639: 30) | 600 | ko -0.02em, en -0.025em | 한 문장 현황, 들어가기 전 화면 제목 |
| `text-title` | 22px (≤639: 20) | 32px (≤639: 30) | 28px (≤639: 26) | 600 | ko -0.012em, en -0.015em | 화면 제목, 이슈 패널 제목 |
| `text-heading` | 15px | 24px | 22px | 600 | -0.005em | 카드 머리, 구역 제목 |
| `text-body` | 15px | 26px | 24px | 400 | 0 | 문장, 설명 |
| `text-ui` | 14px | 22px | 20px | 500 | 0 | 표·목록 줄의 제목, 메뉴, 이슈 카드 제목 |
| `text-small` | 13px | 20px | 18px | 400 | 0 | 보조 설명, 상태 이름, 사람 이름, 날짜·경과 |
| `text-meta` | 12px | 16px | 16px | 400 / 500 | 0 | Mono 번호, 깃발, 작은 표지 |
| `text-figure` (Mono) | 34px (≤639: 28) | 40px (≤639: 32) | 같음 | 500 | -0.03em | 핵심 숫자 |

- 표제(`h1`, `h2`)는 `text-wrap: balance`, 한글은 `word-break: keep-all`.
- 13.5px 같은 반 픽셀 크기와 `text-[12.5px]` 같은 임의 크기를 쓰지 않습니다. 위 단계에서 고릅니다.
- 자간을 넓힌 작은 머리말(eyebrow)은 쓰지 않습니다. 맥락은 제목 위 `text-small` `muted` 한 줄로 줍니다.

## 3. 색

상태 색 규칙:

- 상태 색은 점(8px 원)과 막대 조각에만 씁니다. 글자 색이나 넓은 배경으로 쓰지 않습니다.
- 상태는 언제나 **점 + 이름**을 같이 씁니다. 색만으로 구분하지 않습니다(색각 이상 대비).
- 완료 항목은 `muted` 글자로 한발 물러섭니다. 취소는 회색 점 + 제목 가운데 줄, 완료 열 아래 접힌 묶음.
- 글자 색 토큰은 `canvas`, `surface`, `sunken`, `accent-wash` 위에서 4.5:1 이상입니다. 바꿀 때는 대비를 다시 계산합니다.

주홍과 버튼 규칙:

- 주홍이 화면에 나오는 곳은 주의 표시뿐입니다(5장의 "주의 표시"). 오류도 주홍을 쓰지 않습니다.
- 한 문장 현황의 주의 숫자는 주홍 글자로만 씁니다. "7일 넘게 멈춤" 칸은 0보다 크면 위쪽 2px 주홍 줄 + 주홍 숫자.
- 한 화면에서 주홍이 칠해진 면(`accent-wash`)은 2~3곳을 넘기지 않습니다.
- 그래프 안에서 주홍은 "지남"(끝나는 날이 지난 구간)과 "넘어온 일"에만 씁니다. 남은 일이 기준선보다 많다고, 끝낸 일이 적다고 주홍을 칠하지 않습니다.
- **주 버튼은 잉크색**입니다. 화면마다 주 동작 하나(로그인, 다시 확인, 다시 시도, 이후 회사 만들기)만
  `btn btn-primary`(`ink` 바탕 + `on-ink` 글자). 나머지 버튼은 `btn`(`surface` 바탕 + 고리).
- 링크는 `ink` 글자 + `rule-strong` 밑줄(`.link`)입니다.

## 4. 간격, 모양, 높이, 움직임

**간격**은 4px 단위: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80`.

| 자리 | 값 |
| --- | --- |
| 화면 좌우 여백 | 40 (≥1024) / 24 (640~1023) / 16 (≤639) |
| 내용 최대 폭 | 1200px, 가운데 |
| 카드 안쪽 | 20 (≤639 숫자 판은 16) |
| 카드 사이, 구역 사이 | 24 |
| 화면 머리 → 첫 카드 | 32 |
| 표 줄 | 위아래 12 (한 줄 46px 안팎). 접힌 줄은 위아래 16 |
| 묶음 머리 위 | 20 |

**모서리**

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `rounded-mark` | 3px | 프로젝트 표식 |
| `rounded-flag` | 4px | 깃발, `kbd` |
| `rounded-control` | 8px | 버튼(40px), 메뉴 줄, 검색창, 토글 |
| `rounded-item` | 10px | 큰 버튼·입력(48px), 이슈 카드, 점선 상자 |
| `rounded-card` | 12px | 카드 |
| `rounded-sheet` | 16px | 들어가기 전 화면 카드, 이슈 패널(왼쪽 모서리) |
| `rounded-full` | — | 머리글자 원, 필터 칩, `예시` 표지 |

**경계와 높이**

| 단계 | 라이트 | 다크 | 쓰는 곳 |
| --- | --- | --- | --- |
| 0 | `canvas` | `canvas` | 바탕, 옆 메뉴 |
| 1 `shadow-elev-1` | 고리 + `0 1px 2px` ink 4% | 고리만 | 카드, 이슈 카드, 선택된 메뉴, 버튼, 검색창 |
| 2 `shadow-elev-2` | 고리 + `0 12px 32px -12px` ink 18% | 고리 + 검은 그림자 | 로그인 미리 보기, 팝업 |
| 패널 `shadow-panel` | 고리 + `0 16px 40px -12px` | 같음 | 이슈 패널 |

- 카드 안 줄 구분은 카드 안쪽 여백(20px)에서 시작하고 끝나는 1px `rule` 선입니다(`after:inset-x-5`). 표 머리에 회색 바탕을 깔지 않습니다.
- hover는 `hover` 바탕, 또는 이슈 카드처럼 고리를 `rule-strong`으로 진하게 합니다.

**움직임**

- 시간: 빠름 120ms(hover, 눌림), 보통 200ms(패널 열림, 펼침), 첫 화면 등장 280ms.
- 곡선: `cubic-bezier(0.2, 0.7, 0.2, 1)` 하나만(`ease-tool`).
- 첫 화면은 구역별로 30ms씩 늦춰 아래로 4px 떠오르며 나타납니다. 데이터가 다시 불러와질 때는 움직이지 않습니다.
- 막대(진행률, 부하)는 처음 그릴 때만 왼쪽에서 채워집니다. 주별 기둥(`.cols`)은 처음 그릴 때만 아래에서 올라옵니다. 선 그래프는 움직이지 않습니다.
- 기다리는 중 표시(`.busy-dot`)는 1초 주기로 흐려졌다 돌아오고, 되돌리기 버튼 아래 2px 줄(`.undo-clock`)은 10초 동안 줄어듭니다. 둘 다 글자와 함께만 씁니다.
- `prefers-reduced-motion: reduce`이면 모든 움직임을 끕니다.

- 표와 사람 목록은 화면 폭이 아니라 **카드 폭**(container query `@[35rem]` = 560px)으로 접습니다.
- 페이지 전체는 390px에서 가로로 스크롤되지 않습니다. 가로 스크롤은 탭 줄만 합니다.
- 들어가기 전 화면: 1024 이상 두 칸(왼쪽 폼, 오른쪽 `예시` 미리 보기), 1023 이하 폼만 한 칸.

## 6. 컴포넌트 규칙

### 틀 (옆 메뉴, 상단 막대)

- 틀(옆 메뉴, 상단 막대, 이슈 패널, 단축키)은 로그인과 회사 확인(`/api/me`)이 끝난 뒤에만 그립니다. 그 전에는 아래 "들어가기 전 화면"만 보입니다.
  빌드된 HTML에는 중립적인 "확인하는 중" 화면만 들어가고 메뉴 글자는 들어가지 않습니다.
- 옆 메뉴(1024px 이상): `canvas` 바탕, 오른쪽 1px `rule`. 맨 위에 회사 표식(32px, Mono 두 글자) + 회사 이름 + "업무 보드".
  메뉴 줄은 36px, 16px 선 아이콘 + 이름. 선택된 메뉴는 `surface` 바탕 + `elev-1` + 굵게. 마우스나 초점이 가면 오른쪽에 단축키(`g o` 등).
  맨 아래에 언어·밝기 토글과 단축키 요약(`/` 검색, `c` 새 이슈, `s` 상태, `j` `k` 이동, `Enter` 열기, `Esc` 닫기).
- 상단 막대: 반투명 `canvas` + 흐림, 아래 1px `rule`, 스크롤해도 고정. 1024px 이상은 경로(`acme-health / 개요`), 검색창(`/`), `새 이슈` 버튼(`c`), 계정과 로그아웃.
  1024px 이상에서 다른 항목(경로, 동기화 줄, 새 이슈, 계정)이 쓰고 남은 폭이 240px보다 좁으면 검색창을 접어 36px 아이콘 버튼(`surface` + `elev-1`, 이름 "검색 (/)")으로 둡니다. 잘린 입력 칸은 그리지 않습니다. 누르거나 `/`를 누르면 검색창이 펼쳐지고(최소 200px) 그동안 동기화 줄은 숨으며, 비운 채 초점이 떠나면 다시 접힙니다.
  경로는 회사 이름부터 말줄임으로 줄고 화면 이름은 늘 다 보입니다. 1024~1279px에서는 계정 이름과 "개발용 사용자" 글자를 숨깁니다(화면 읽기에는 남음). 같은 폭에서 동기화 줄의 "마지막 동기화 N분 전" 글자만 `sr-only`로 두고(점과 `title`은 남음), 동기화하는 중, 실패, 방금 누른 동작의 결과("동기화를 시작했습니다" 등)는 늘 글자로 보입니다.
  동기화 줄의 글자는 1024px 이상에서 최대 208px, 실패 이유는 최대 160px(1279px 이하는 `sr-only`)로 말줄임하고, 문장 전체는 `title`에, 알림은 화면 읽기용 live region에도 둡니다.
  검색창을 접은 뒤에도 막대가 넘치면 "좁은 막대"로 바꿉니다: 토큰 짧은 꼴 글자를 빼고, 동기화 글자는 최대 128px, 실패 이유는 `sr-only`, `새 이슈`는 더하기 아이콘만(이름은 화면 읽기와 `title`에) 둡니다. 막대가 넓어지거나 알림, 동기화 상태, 토큰 상태, 언어가 바뀌면 다시 잽니다.
  접힌 검색창을 `Esc`로 닫으면 초점이 검색 버튼으로 돌아가고, 다른 곳을 눌러 닫으면 초점을 옮기지 않습니다.
  개발 모드에서는 계정 자리에 개발용 사용자 선택이 있습니다.
- 언어 토글과 밝기 토글은 같은 모양(`.seg`: `sunken` 바닥 위 선택된 칸만 흰 판)입니다. 언어 이름은 늘 그 언어로 쓰고, 639px 이하는 `KO` / `EN`(Mono). 밝기는 해·달 아이콘.
- 아바타(`Avatar`)는 둥근 원입니다. GitHub 프로필 사진이 있으면 사진(`object-cover`), 없거나 불러오지 못하면 이름 머리글자(`ink` 바탕)로 되돌립니다. 크기는 `sm` 20px / `md` 24px / `lg` 32px. 담당자·구성원·활동 등 사람을 보이는 모든 곳이 같은 컴포넌트를 씁니다. 장식이라 `aria-hidden`이고 이름은 옆 글자가 말합니다.

### 화면 머리

- `text-small` `muted` 한 줄(맥락) → `text-title` 제목 → `text-body` 한 문장. 굵은 줄을 긋지 않습니다.
- 개요는 맥락 줄(날짜 · 열린 일 · 주기, `·`로 구분) → `display` 한 문장 → 숫자 판 한 장(4칸 + 아래 팀 막대와 범례).

### 카드

- `.card`: `surface` 바탕, `elev-1` 고리, 12px 모서리. 머리: 제목(`heading`) + 개수(Mono `meta`) + `muted` 설명 + 오른쪽 이동 링크와 단축키. 머리 아래 선은 긋지 않습니다.
- 카드 안 목록은 줄 사이 안쪽 선, 좌우 20px. 빈 상태는 카드 안에 점선 상자.

### 표 (손봐야 할 일, 검색, 회의록)

- 열 머리 36px, `meta` `muted` 글자, 아래 1px `rule`. 바탕은 깔지 않습니다: `저장소 #번호 / 제목 / 상태 / 담당 / 경과`.
- 묶음 머리: 깃발 + 개수(Mono) + 이유(`muted`). 줄은 hover와 초점에 `hover` 바탕.
- 카드 폭 560px 미만에서는 한 줄이 세 줄로 접힙니다: 번호·경과 / 제목 / 상태·담당.

### 이슈 카드 (보드)

```
booking-api #102 · 작업            긴급
예약 조회 API 페이지네이션
이민준          PR 1 · 댓글 2 · 1일 전
```

- `surface`, `elev-1`, 10px 모서리, 안쪽 14 × 16. 첫 줄 Mono 번호 + Sans 종류, 제목은 `ui` 500 두 줄까지, 마지막 줄 담당자와 PR·댓글·경과(Sans).
- 완료 카드는 바탕 없이 고리만 남기고 제목을 `muted`로.
- 보드 열이 이미 상태를 말하므로 상태 줄은 생략합니다(필요하면 `showStatus`로 점 + 이름).
- 긴급이고 아직 할 일이면 왼쪽 3px 주홍 거터. 우선순위는 설정에서 켠 경우에만 보입니다. 높음은 `ink-soft` 글자 "높음"만.
- hover: 고리를 `rule-strong`으로 + 옅은 그림자. 클릭하면 이슈 패널(`?issue=`)이 열립니다. 카드 안에 다른 링크를 두지 않습니다.
- 값을 바꾸는 중이면 마지막 줄의 PR·댓글·경과 자리에 `.busy-dot` + "저장 중…" / "GitHub에서 닫는 중…" / "GitHub에서 다시 여는 중…"을 씁니다(`aria-busy`).
- 끄는 동안 원래 자리의 카드는 불투명도 0.4(`.card-lifted`)로 남습니다.

### 보드 (내 작업, 프로젝트별, 사람별)

- 열 머리는 판 없이 점 + 상태 이름 + 개수, 할 일 / 진행 중 / 리뷰 중 열은 오른쪽 끝에 `+`(그 상태로 새 이슈). 머리 높이는 28px로 맞춥니다. 열 수는 화면이 아니라 보드가 가진 폭으로 정합니다(`boardCols`, container query): 544px 미만 1열, 1024px 미만 2열, 그 이상 4열. 한 열이 240px보다 좁아지지 않게 하려는 것입니다.
- 640px 이상에서는 카드를 다른 열로 끌어 상태를 바꿉니다(아래 "카드 값 바꾸기"). 639px 이하는 끌기를 끕니다.
  끄는 동안 놓을 수 있는 열은 `sunken` 바탕 + `rule-strong` 점선 테두리(`.drop-col[data-drop="can"]`), 포인터 아래 열은 `focus` 2px 실선 + `drop-wash` 바탕(`over`), 놓을 수 없는 열은 불투명도 0.45(`off`)입니다. 면이 함께 바뀌어 어디에 놓을지 눈에 잘 띕니다.
  카드는 자기 보드 안에서만 옮깁니다. 사람별 보드에서는 그 사람의 열 사이에서만 옮기고, 담당자는 바뀌지 않습니다. 접힌 취소 묶음은 완료 열에 속해, 취소 카드를 완료 열에 놓으면 완료가 됩니다.
- 사람별 보드는 사람마다 머리(머리글자 원, 이름, 진행·리뷰 수, 몰림 깃발) + 같은 열 묶음입니다. 한 열로 쌓일 때는 빈 열을 숨깁니다. 완료 열은 취소된 일만 있어도 비지 않은 것으로 봅니다.

### 상태 표시

- 기본형: 8px 점 + 상태 이름(`small`, `ink-soft`). 예: `● 리뷰 중`.
- 요약형: 진행률 막대, 또는 `완료 2 · 리뷰 중 3` 같은 점 붙은 숫자 줄(숫자는 Mono).
- 상태 이름은 할 일 / 진행 중 / 리뷰 중 / 완료 / 취소. 다른 말로 바꾸지 않습니다.

### 주의 표시

주홍을 쓰는 유일한 요소입니다. 모양은 **깃발**: 높이 22px, 주홍 글자 + 반투명 주홍 1px 고리 + 4px 모서리, 굵기 600.

| 종류 | 조건 | 표시 |
| --- | --- | --- |
| 긴급 | 우선순위 `urgent`이고 완료가 아님 | 깃발 `긴급` (`accent-wash` 바탕), 아직 시작 전이면 줄 왼쪽 3px 거터 |
| 멈춤 | 열린 이슈의 마지막 활동이 7일 이상 전 | 줄·카드 불투명도 0.55 + 경과 자리에 깃발 `12일째` |
| 담당자 없음 | 열린 이슈에 담당자가 0명 | 담당자 자리에 점선 원 + 주홍 글자 `담당자 없음` |
| 리뷰 대기 | 리뷰 요청된 열린 PR이 24시간 이상 | 묶음 머리 깃발 `리뷰 대기`, 경과 자리에 대기 일수 |
| 이슈 없음 | 회의 할 일이 이슈로 이어지지 않음 | 깃발 `이슈 없음` |
| 넘어온 일 | 이전 주기에서 넘어와(되돌리지 않은 넘기기) 아직 끝나지 않음. 주기 계획 화면에서만 | 깃발 `넘어온 일`, 마우스를 올리면 이전 주기 이름 |
| 곧 만료 | 토큰 연결의 토큰이 7일 안에 만료(`tokenExpiresSoon`) | 깃발 `곧 만료` + 굵은 `ink-soft` "3일 남음" |
| 연결 멈춤 | 토큰 연결이 토큰 문제로 동기화를 멈춤(`expired`, `revoked`, `invalid`, `token_required`) | 깃발 `연결 멈춤` + 굵은 `ink-soft` 이유("토큰 만료", "토큰 취소됨", "조직 접근 안 됨", "토큰 필요") + 할 일 한 줄 |

GitHub 요청 한도 때문에 잠시 쉬는 동기화(`syncPausedUntil`)는 기다리면 저절로 풀리므로 주의 표시가 아닙니다. 주홍 없는 표지(`.tag`) "동기화 쉬는 중" + `muted` "오후 6:22에 다시 시작"으로 씁니다.

멈춘 줄은 흐려지지만 깃발은 흐려지지 않습니다. 흐려짐은 "잊혀 가는 중", 깃발은 "그래서 봐야 함"을 뜻합니다.

### 사람별 부하 막대

- 한 줄에 한 사람: 머리글자 원, 이름, 막대, 열린 수(Mono), 지금 하는 일 하나.
- 막대는 그 사람의 열린 일을 상태별로 쌓은 것입니다: 진행 중, 리뷰 중, 할 일(옅게). 길이의 기준은 팀에서 열린 일이 가장 많은 사람(100%).
- "몰림" 깃발: 진행 중 + 리뷰 중이 4건 이상이고 팀 중앙값의 2배 이상일 때만. 중앙값은 맡은 일 없는 팀원까지 포함해 셉니다.
- 맡은 일이 0건이면 막대 대신 `muted` 글자 "맡은 일 없음".

### 진행률 막대

- 높이 6px, 바닥 `sunken`, 모서리 3px. 완료 / 리뷰 중 / 진행 중 / 할 일 순서로 왼쪽부터 쌓습니다.
- 옆이나 아래에 숫자를 항상 함께: `완료 1/6 · 17%`. 막대만 두지 않습니다. 전체가 0건이면 "아직 일이 없습니다".

### 그래프 (남은 일 추이, 한 주에 끝낸 일, 일정)

그래프는 세 가지뿐이고, 이미 있는 판 안에 붙입니다. 보고서 메뉴나 고르는 위젯은 만들지 않습니다.

- **남은 일 추이**: 개요의 주기 카드(`canvas` 판) 아래쪽. 머리 `small` 600 `ink-soft` "남은 일 추이" + 오른쪽 "남은 일 6건"(숫자 Mono).
  높이 56px 선 그래프: 가로는 주기의 시작일부터 끝나는 날까지, 세로는 이슈 건수(0이 바닥 1px `rule-strong` 선). 위쪽에 15% 여유를 둡니다.
  남은 일은 2px `ink-soft` 실선(둥근 끝), 마지막 기록은 8px 점 + 바탕색 2px 고리. 기준선은 첫 기록일의 범위 건수에서 끝나는 날 0건까지 1px `muted` 점선(4 3).
  기록이 빠진 날은 선을 끊고(앞뒤를 잇거나 앞 값을 끌어오지 않음), 혼자 남은 날은 4px 점입니다. 끊긴 곳이 있으면 아래에 "기록이 빠진 날은 선을 끊었습니다." 한 줄.
  아래에 시작일·끝나는 날(Mono `meta`), 범례(짧은 실선 "남은 일", 짧은 점선 "기준선"), 크기를 켰으면 오른쪽에 "크기로 보면 N% 남음".
- **한 주에 끝낸 일**: 프로젝트 화면의 프로젝트 카드마다, 진행률 아래 `rule` 줄 다음. 머리 `small` `muted` "한 주에 끝낸 일" + 오른쪽 "이번 주 2건"(숫자 Mono `ink`).
  최근 8주(월~일, 서울 시각) 기둥 8개, 높이 32px, 기둥 폭 24px까지, 위쪽 모서리만 4px. 색은 `status-done`, 지난 주는 불투명도 0.55, 이번 주는 그대로.
  0건인 주는 2px `rule-strong` 조각으로 자리를 보입니다. 아래 양 끝에 "7주 전" / "이번 주"(`meta` `muted`).
- **일정**: 프로젝트 화면에서 프로젝트를 고르면 생기는 `보드` / `일정` 탭(`?view=schedule`)의 판 하나. 머리 "일정" + `muted` 설명, 그 아래 한 문장
  (지난 채 끝나지 않은 일정 수, 없으면 다음 날짜와 남은 날, 그것도 없으면 지난 일정이 없다는 말).
  묶음은 주기 → 마일스톤 → 날짜 없음. 줄은 왼쪽 글자(이름, 아래 `small` `muted` 날짜·상태·`완료 3/8`) + 오른쪽 막대 칸이고, 카드 폭 560px 미만에서는 막대 칸이 글자 아래로 내려갑니다.
  가로축은 모든 줄이 같이 쓰는 하나이고 카드 폭에 맞춰 늘고 줄어 가로 스크롤이 없습니다. 범위는 일정의 모든 날짜와 오늘, 양 끝 4% 여유, 최소 14일. 위에 시작일·끝 날짜(Mono `meta`)와 "오늘 11.17".
  날짜는 그 날의 가운데에 놓습니다. 오늘은 줄마다 1px `ink-soft` 세로선, 바닥에 1px `rule` 가로선.
  주기는 시작일~끝나는 날 6px 막대(`rule-strong`, 시작 전은 `sunken` + 고리), 그 안에 왼쪽부터 끝낸 비율만큼 `status-done`. 끝난 주기는 불투명도 0.55.
  마일스톤은 마감일의 10px 마름모(`ink-soft`, 닫힌 것은 `status-done` 0.55). 표식에는 바탕색 2px 고리.
  지난 채 끝나지 않은 줄(열린 마일스톤의 마감일이 지남, 끝난 주기에 끝나지 않은 일이 남음)만 깃발 `N일 지남`과, 막대 끝에서 오늘 선까지 2px 주홍 선("지남" 구간)을 둡니다.
  줄은 링크입니다(`data-row`): 마일스톤은 GitHub(새 창), 주기는 주기 계획 화면. 마감일 없는 마일스톤은 막대 없이 "날짜 없음" 묶음에만.
  빈 상태: 마일스톤도 주기도 없으면 점선 상자 하나, 날짜 있는 것이 없으면 막대 자리에 점선 상자 + 날짜 없음 묶음.
- 셋 다 숫자를 글자로 함께 둡니다. 색이나 길이만으로 읽게 하지 않습니다. 마우스를 올리면 그 날·그 주의 값이 `title`로 보입니다.
- 화면 읽기 프로그램: 남은 일 추이는 그래프를 숨기고(`aria-hidden`) 날짜·남은 일·기준선 표(`sr-only`)를 둡니다. 주별 기둥은 `role="img"` + 8주 값을 모두 읽는 `aria-label`. 일정은 막대를 숨기고 줄의 글자(종류, 이름, 날짜, 상태, 지남)가 링크 이름이 됩니다.
- 빈 상태: 기록이 아직 없는 주기는 그래프 자리에 점선 상자 "아직 기록이 없습니다. 남은 일은 하루 한 번 기록되고, 첫 기록 뒤에 선이 그려집니다."
- 축 이름, 눈금, 격자선은 그리지 않습니다. 두 개의 세로 축을 쓰지 않습니다.

### 이슈 패널

- 오른쪽에서 열리는 560px 패널(휴대폰은 전체 너비), 왼쪽 모서리 16px. 머리 56px: Mono 번호 + `닫기 Esc` 버튼.
- 제목(`title`) 아래 속성은 고리 두른 2열 표(상태, 담당자, 종류, 주기, 우선순위, 크기, 마지막 활동).
- 상태, 우선순위, 크기는 표 안에서 바로 고칩니다. 값 자체가 버튼(`.prop-trigger`)이고, hover와 초점에 `hover` 바탕 + `rule-strong` 고리가 생기며 오른쪽에 작은 `▾`가 붙습니다.
  누르면 바로 아래에 짧은 목록(`.menu`, `elev-2`, 8px 모서리, 줄 32px)이 열립니다. 고른 값은 굵게 + 체크 표시, 상태 목록은 점 + 이름 + 오른쪽 `kbd` 숫자(1~5).
  `↑` `↓` `Home` `End`로 움직이고 `Enter`로 고르며, `Esc`는 목록만 닫고 패널은 닫지 않습니다. 목록이 열린 동안 숫자 키는 그 항목을 고릅니다.
  우선순위와 크기는 설정에서 켠 경우에만 줄이 있고, 켰으면 값이 없어도 "정하지 않음"(`muted`)으로 보입니다. 긴급은 값 자리에 긴급 깃발.
- 표 바로 아래에 `small` `muted` 한 줄 "보드에서 바꿈 · 이민준 · 3분 전". 보드에서 아무도 바꾼 적이 없으면 줄이 없습니다.
- 본문과 댓글은 마크다운으로 렌더링합니다(`Markdown`, 의존성 없는 자체 파서): 제목·목록·굵게·기울임·링크·인라인/블록 코드·인용. 원시 HTML과 이미지는 글자로 두고, 링크는 `safeHttpUrl`을 통과한 http(s)만 새 탭으로 엽니다. 글자 단계는 본문 `body`·제목 `heading`을 쓰고 링크·코드에 주홍을 쓰지 않습니다. 본문이 비면 `muted` 한 줄 "설명이 없습니다".
- 그 아래 연결된 PR, 하위 일, 이 일이 나온 회의, 대화 구역. 구역 머리 아래 선은 긋지 않습니다. 셋 중 빈 구역은 머리를 그리지 않고 맨 아래에 `small` `muted` 한 줄로 모읍니다("연결된 PR 없음 · 하위 일 없음 · 회의 없음"). 대화 구역은 입력 칸이 있어 늘 보입니다.
- **담당자 바꾸기**: 담당자 값(또는 단축키 `a`)이 회사 팀원 목록(`.menu.menu-wide`, `aria-multiselectable`)을 엽니다. 맨 위 `meta` 한 줄 "회사 팀원 중에서 고릅니다".
  줄마다 체크 상자(고르면 `ink` 바탕 + 체크) + 머리글자 + 이름 + Mono 아이디. `Space`/`Enter`로 고르고 빼며, 고르는 동안은 아무것도 보내지 않습니다.
  아래 줄의 `담당자 저장`(또는 `Ctrl`/`⌘`+`Enter`)이 한 번에 GitHub에 보내고, `Esc`나 바깥 클릭은 저장하지 않고 닫습니다. 10명이 차면 나머지 줄은 흐리게 막습니다.
  보내는 동안 값 옆에 `.busy-dot` + "GitHub에 저장 중…". GitHub이 거절하면(422 `assignee_not_collaborator`) 표 아래에 오류 규칙대로 "이 저장소에 지정할 수 없는 사람" + 빼거나 협업자로 초대하라는 한 줄.
  GitHub이 일부만 지정했으면 표 아래 왼쪽 2px 줄 한 줄로 이름을 말합니다. 실패 이유별 다시 시도는 위 "카드 값 바꾸기" 표와 같습니다(같은 목록으로 바꾸기라 새 키로 다시 보내도 해가 없음).
- **댓글**: 대화 구역 맨 아래 입력 칸(3줄, 마크다운) + `댓글 남기기`, `Ctrl`/`⌘`+`Enter`로 보냅니다. 아래 `meta` 한 줄로 GitHub에는 앱 이름으로 올라가고 내 아이디가 붙는다고 말합니다.
  보낸 댓글은 답이 오면 곧바로 대화 맨 아래에 붙습니다. GitHub이 답하지 않았거나(504, 연결 끊김), 처리 중이거나, 5xx면 댓글이 이미 올라갔을 수 있으므로
  새 이슈 폼처럼 입력 칸을 잠그고(`sunken` 바탕, 읽기 전용) `같은 내용으로 다시 보내기`(같은 요청 키)만 둡니다. `취소하고 고치기`는 GitHub에서 먼저 확인하라는 말과 함께 둡니다.
  패널을 닫아도 적던 내용과 잠금은 이슈마다 남습니다.
- 열리면 닫기 버튼에 초점, 닫히면 연 자리로 초점이 돌아갑니다.

### 새 이슈 (이슈 패널의 만들기 모드)

- 새 화면을 만들지 않고 이슈 패널을 `?issue=new`로 엽니다. 여는 곳은 세 군데입니다: 상단 막대의 `새 이슈` 버튼(639px 이하는 페이지 위 동기화 줄 오른쪽),
  단축키 `c`, 보드 열 머리 끝의 `+`(할 일 / 진행 중 / 리뷰 중 열만, 그 상태로 시작). 사람별 보드와 내 작업의 `+`는 그 사람을 담당자로 미리 고릅니다.
- 머리는 `새 이슈`(Sans `meta`). 본문은 제목(`title`) → 한 줄 설명 → 저장소(Mono, 프로젝트 화면이면 그 프로젝트의 첫 저장소, 아니면 마지막에 쓴 저장소) →
  제목 입력(48px, 열리면 여기에 초점) → 설명(마크다운) → 상세 패널과 같은 고리 두른 2열 표(상태, 담당자, 라벨, 설정에서 켠 경우 우선순위·크기).
  만든 뒤 보일 모습과 같은 자리에 같은 순서로 둡니다.
- 담당자와 라벨은 누름 칩(`aria-pressed`)입니다. 고른 칩은 1.5px `ink` 고리 + 체크 표시로, 색만으로 구분하지 않습니다. 라벨 색은 10px 사각 표식에만 씁니다.
  라벨이 12개를 넘으면 칩 위에 찾기 칸을 둡니다. 보관된 저장소는 목록 맨 아래에서 고를 수 없게 둡니다.
- 바닥에 붙은 줄에 주 버튼 `이슈 만들기`(잉크색) 하나와 `Ctrl`/`⌘` `Enter` 안내. 보내는 동안 버튼을 끄고, 한 번 누르면 요청은 하나만 갑니다.
- 만들면 패널이 그 이슈 보기로 바뀌고 맨 위에 `sunken` 바탕 한 줄 `repo #N 만듦 · GitHub에서 열기`, GitHub이 지정하지 않은 담당자가 있으면 그 아래 한 줄.
  보드는 다시 불러와 새 카드가 그 열 맨 위에 옵니다. GitHub에만 만들어지고 보드 저장이 늦어진 경우(202)는 "다음 동기화 뒤에 나타남"과 저장되지 않은 항목을 말합니다.
- 오류는 아래 "오류" 규칙(주홍 없음, 왼쪽 2px 줄) + 해결 방법 한 줄. GitHub 연결 문제처럼 다시 보내도 되는 오류에는 `다시 시도`를 두고 같은 요청 키로 보냅니다.
- `Esc`로 닫아도 적던 내용은 남아 있다가 다음에 열면 이어집니다. 만들고 나면 비웁니다.

### 카드 값 바꾸기 (보드, 이슈 패널)

카드의 상태, 우선순위, 크기는 세 군데에서 바꿉니다: 보드에서 끌기(640px 이상), 단축키 `s` + 숫자, 이슈 패널 속성 표. 결과는 모든 화면에 같이 보입니다.

| 바꾸는 값 | 보이는 방식 | 실패하면 |
| --- | --- | --- |
| 할 일 · 진행 중 · 리뷰 중 사이, 우선순위, 크기 | 곧바로 새 자리·값으로 보이고 카드에 "저장 중…" | 원래 칸·값으로 돌아가고 실패 알림 |
| 완료 · 취소로 (GitHub에서 닫음) | 곧바로 완료·취소 칸으로 옮기고 카드에 "GitHub에서 닫는 중…", GitHub는 뒤에서 닫음. 10초 동안 "되돌리기" | 원래 칸으로 돌아가고 실패 알림 |
| 완료 · 취소에서 열린 상태로 (GitHub에서 다시 엶) | 곧바로 옮기고 "GitHub에서 다시 여는 중…", GitHub는 뒤에서 엶 | 원래 칸으로 돌아가고 실패 알림 |

- 한 카드에 보낸 변경이 끝나기 전에는 그 카드를 다시 바꿀 수 없습니다(끌기 꺼짐, 패널 값 버튼 꺼짐).
  그사이 `s` + 숫자나 `되돌리기`를 누르면 무시하지 않고 "앞 변경을 저장하는 중입니다"라고 말합니다(`s`는 위쪽 안내 자리, 되돌리기는 그 알림 안).
- 되돌리기는 이전 상태로 한 번 더 바꾸는 것입니다. 완료·취소를 되돌리면 GitHub에서 다시 열고, 그 상태를 보드 값으로 고정합니다.
- 보낼 때 보던 값의 시각(`expectedUpdatedAt`)을 함께 보냅니다. 그사이 다른 사람이 바꿨으면(409) 최신 값을 다시 불러오고 다시 바꿔 달라고 말합니다.
- **알림**(`.notice`): 화면 왼쪽 아래(1024px 이상은 옆 메뉴 오른쪽, 639px 이하는 아래 전체 폭)에 하나만, `surface` + `elev-2` + 10px 모서리. 초점을 가져가지 않습니다(`aria-live`).
  - 옮김: 상태 점 + "booking-api #102 완료로 옮김" + `muted` "GitHub에서 닫았습니다." + `되돌리기` 버튼(아래 줄이 10초 동안 줄어듦).
  - 실패: 오류 규칙대로 주홍 없이 왼쪽 2px `ink-soft` 줄, 첫 줄 "… 값을 바꾸지 못했습니다", 둘째 줄 이유와 해결 방법. 다시 보내서 나아질 수 있을 때만 `다시 시도`.
    GitHub이 답하지 않은 경우(504, 연결 끊김)는 GitHub에서 이미 바뀌었을 수 있으므로 최신 값을 다시 불러오고, `다시 시도`는 같은 요청 키로 보냅니다.
    502는 서버가 그 답을 요청 키에 저장해 같은 키로는 같은 실패만 돌아오므로, 다시 불러온 뒤 `다시 시도`를 새 키로 보냅니다(두 번 닫거나 열어도 보드에는 해가 없음).
- 실패 이유별 문구:

| 경우 | API | 문구의 요지 | 다시 시도 |
| --- | --- | --- | --- |
| 권한 없음 | `403 github_write_not_granted` | GitHub App에 이슈 쓰기 권한이 없음, 관리자가 GitHub에서 승인 | 없음 |
| GitHub 연결 안 됨 | `404 not_found` | 이슈가 없거나 저장소의 GitHub 연결이 끊김, 설정에서 확인 | 없음 |
| 보관된 저장소 | `409 repository_archived` | 닫거나 다시 열 수 없음, GitHub에서 보관 해제 | 없음 |
| 꺼진 항목 | `409 field_disabled` | 설정에서 꺼져 있음 | 없음 |
| 다른 사람이 먼저 바꿈 | `409 conflict` | 최신 값을 불러왔으니 다시 | 없음 |
| GitHub 잠시 안 됨 | `502 github_unavailable` | 바꾸지 못함, GitHub에서 이미 바뀌었는지 확인한 뒤 다시(다시 불러옴) | 있음(새 키) |
| GitHub 응답 없음 | `504 github_unavailable`, 연결 끊김 | 이미 바뀌었을 수 있어 다시 불러옴 | 있음(같은 키) |
| 처리 중 | `409 request_in_progress` | 잠시 뒤 다시 | 있음(같은 키) |

### 주기 계획 (`/sprints`, `g c`)

- 주기를 켠 회사에서만 메뉴에 보입니다. 꺼져 있으면(또는 쓰는 중에 409 `sprints_disabled`가 오면) 화면 머리 아래 점선 상자 한 줄로 꺼져 있다고 말하고 설정으로 가는 링크를 둡니다.
- 화면 머리의 한 문장: "이번 주기(이름)에는 8건이 있고 6일 남았습니다. 대기 목록에는 12건이 있습니다." 진행 중인 주기가 없으면 다음 주기가 며칠 뒤 시작하는지, 주기가 하나도 없으면 첫 주기를 만들라고 말합니다. 오른쪽에 `새 주기` 버튼.
- 판 세 장: 대기 목록, 이번 주기, 다음 주기. 판이 가진 폭(container query)으로 놓습니다: 640px 미만 한 열(대기 목록 → 이번 → 다음), 640~895px 두 열(왼쪽 대기 목록, 오른쪽에 두 주기를 쌓음), 896px 이상 세 열.
- 주기 판 머리: `small` `muted` 칸 이름(진행 중인 주기나 다음 주기가 여럿이면 그 자리가 고르는 선택 상자. `a`는 이번 주기 칸에 보이는 주기에 넣음) + 오른쪽 `고치기` → `heading` 주기 이름 → 날짜 범위 → 요약 한 줄 "8건 · 크기 S 2 · M 5 · 남은 날 6일". 건수는 취소를 빼고 셉니다. 크기는 설정에서 켠 경우, 크기가 정해진 일이 있을 때만 씁니다. 시작 전 주기는 "3일 뒤 시작".
- 줄: 카드 안 목록 규칙(줄 사이 안쪽 선, `hover` 바탕). 첫 줄 Mono 번호 + 종류, 오른쪽에 깃발(`넘어온 일`, 긴급)과 크기(Mono `S`/`M`/`L`) → 제목(`ui` 500, 두 줄까지) → 담당자와 상태(점 + 이름).
  줄은 이슈 패널을 여는 버튼(`data-row`)입니다. 대기 목록 줄 왼쪽에는 고르기 상자(`role="checkbox"`, 고르면 `ink` 바탕 + 체크), 주기 줄 오른쪽에는 `대기 목록으로 빼기` 아이콘 버튼.
- 대기 목록 판 머리 아래에 고른 동안만 `sunken` 띠: "3건 고름" + `이번 주기에 넣기`(주 버튼, 잉크색) + `다음 주기에 넣기` + `고르기 풀기`. 고른 것이 없으면 640px 이상에서 `x` `a` 단축키 안내 한 줄.
- 여러 건 넣기는 요청 하나(`{ issueIds }`, `Idempotency-Key`)입니다. 보내자마자 줄이 새 자리로 가고 "저장 중…"(`.busy-dot`)이 붙습니다. 끝나면 알림 자리에 "3건을 (주기)에 넣었습니다", 실패하면 원래 자리로 돌아가고 오류 규칙대로 알림을 띄웁니다.
  끝난 주기(409 `sprint_ended`), 사라진 주기·이슈(404), 그 밖의 4xx는 `다시 시도`가 없습니다(앞의 둘은 목록을 다시 불러옴). 연결 끊김과 5xx만 같은 요청 키로 `다시 시도`.
  `대기 목록으로 빼기` 뒤 초점은 같은 칸의 옆 줄로, 옆 줄이 없으면 대기 목록으로 옮겨 간 그 줄로 갑니다.
- 640px 이상에서는 줄을 다른 판으로 끌어 옮깁니다(대기 목록 ↔ 주기, 주기 ↔ 주기). 고른 줄을 끌면 고른 것 모두가 갑니다. 놓을 수 있는 판 표시는 보드의 `.drop-col` 규칙과 같습니다. 639px 이하는 끌기를 끄고 버튼으로 같은 일을 합니다.
- 주기 만들기·고치기는 화면 머리 아래에 펼치는 카드 폼입니다: 이름(80자까지), 시작일, 끝나는 날(`date` 입력) + 주 버튼 `주기 만들기`/`저장` + `취소`(`Esc`). 열리면 이름 칸에 초점, 닫히면 연 버튼으로 초점이 돌아갑니다.
  빈 이름, 빠진 날짜, 시작일보다 이른 끝나는 날은 보내기 전에 막고, 서버 오류(`name_taken`, `invalid_dates`)는 폼 아래 오류 규칙대로 씁니다.
  고치는 사이 다른 사람이 바꿨으면(`conflict`) 저장 버튼을 끄고 최신 값을 불러와 폼을 그 값으로 다시 채운 뒤 그렇게 했다고 말합니다. 다시 저장은 사람이 내용을 다시 고른 뒤에만 합니다.
  고치던 주기가 끝나거나 닫혀 목록에서 빠지면 저장 버튼을 끄고 저장하지 않았다고 말합니다. 고치기 폼은 절대 새 주기를 만들지 않습니다.
  폼이 열려 있으면 초점이 폼 밖에 있어도(입력 중이 아니면) `Esc`가 폼을 닫습니다. 폼이 열린 동안 대기 목록의 넣기 버튼은 보통 버튼으로 물러섭니다(주 버튼 하나).
- 키보드만으로 계획하기: `g c` → `j`/`k`로 줄 이동 → `x`로 고르기 → `a`로 이번 주기에 넣기(넣은 줄이 사라지면 초점은 바로 아래 줄로) → `Esc`로 고르기 풀기. 다음 주기에 넣기, 빼기, 주기 만들기는 `Tab`으로 가는 버튼입니다.

### 할 일을 이슈로 만들기 (회의록 보기 화면)

- 새 화면이나 패널을 만들지 않고 보기 화면의 `할 일` 카드에서 합니다. 이슈 없는 할 일이 있으면 카드 머리 아래에 `sunken` 띠 하나:
  `저장소` + 선택 상자(Mono, 회의록 프로젝트의 첫 저장소, 아니면 마지막에 쓴 저장소, 아니면 첫 저장소) + 오른쪽에 `이슈 없는 할 일 모두 고르기`.
  고른 동안에는 그 자리가 "2건 고름" + `고르기 풀기` + 주 버튼 `2건 이슈로 만들기`(잉크색, 이 화면의 유일한 주 버튼)로 바뀝니다.
- 이슈 없는 줄: 왼쪽에 고르기 상자(`role="checkbox"`, `.pick-box`), 줄 끝에 깃발 `이슈 없음` + 보통 버튼 `이슈로 만들기`(28px).
  만들면 깃발 자리에 Mono `저장소 #번호` + 상태(점 + 이름)가 오고, 누르면 이슈 패널이 열립니다. 이슈가 생긴 줄에는 고르기 상자가 없습니다.
- 보내는 동안 그 줄은 `.busy-dot` + "만드는 중…". 다른 사람의 요청이 만드는 중이면 "다른 요청이 이슈를 만드는 중", GitHub에만 만들어진 경우(202)는
  Mono 번호 + `muted` "GitHub에 만듦 · 다음 동기화 뒤에 이어짐". 같은 할 일을 두 번 눌러도 요청은 하나만 갑니다.
- 여러 건은 한 건씩 차례로 보냅니다(할 일마다 요청 하나). 띠에 "3건 중 2건째 만드는 중…", 끝나면 알림 자리에 "할 일 3건을 이슈로 만들었습니다",
  일부가 실패하면 "3건 중 2건을…" + 실패한 줄에 이유가 있다는 한 줄. 실패는 그 줄 아래에 오류 규칙(주홍 없음, 왼쪽 2px 줄)으로 씁니다.
  GitHub에 이미 만들어졌을 수 있는 실패(연결 끊김, 504, 처리 중)는 그 줄만 `같은 요청으로 다시 시도`(같은 요청 키, 같은 저장소)로 잠그고, 다른 줄은 그대로 보낼 수 있습니다.
  그 밖의 실패는 `이슈로 만들기` 버튼이 다시 나타납니다(502는 새 키로 보내도 서버가 할 일당 이슈 하나를 지킴).

### 회의록 쓰기와 고치기 (`/notes/view?new=1`, `?id=…&edit=1`)

- 새 화면을 만들지 않고 회의록 보기 화면의 고치기 모드입니다. 목록 머리 오른쪽 `새 회의록`, 보기 화면 머리 오른쪽 `고치기`(주 버튼)로 엽니다.
  보기 화면 순서는 결정한 것 → 할 일(담당자, 기한, 이슈) → 노트입니다.
- 고치기 모드는 같은 자리, 같은 순서: 판 하나(제목 48px 입력, 날짜, 프로젝트, 참석자 누름 칩) → `결정한 것` 카드(번호 붙은 한 줄 입력) → `할 일` 카드(내용, 담당자 선택, 기한 `date`; 639px 이하는 세 줄로 쌓임) → `노트` 카드(마크다운 입력).
  결정과 할 일 줄에서 `Enter`는 바로 아래에 새 줄을 만들고 그 줄로 초점을 옮깁니다. 줄마다 오른쪽에 `빼기` 아이콘 버튼. 이슈와 이어진(또는 이슈를 만드는 중인) 할 일은 뺄 수 없어 버튼이 흐리게 꺼지고, 줄 아래에 Mono 번호와 상태가 보입니다.
- **자동 저장**: 버튼 없이 적는 대로 저장합니다. 입력이 멈추고 1.2초 뒤, 초점이 칸을 떠날 때, 탭이 가려질 때 보냅니다. 저장은 한 번에 하나만 가고, 그사이 적은 것은 끝난 뒤 이어서 보냅니다.
  화면 아래에 붙은 줄(`topbar` 반투명 바탕) 왼쪽에 상태 한 줄(`role="status"`): `.busy-dot` + "저장 중…" / "저장됨 · 방금"(시간이 지나면 "3분 전") / "저장 전" / "아직 저장하지 않음". 오른쪽에 주 버튼 `보기로 돌아가기`(남은 것을 저장한 뒤 이동).
  새 회의록은 화면이 만든 id로 저장해서 답을 못 받고 다시 보내도 두 개가 생기지 않습니다. 제목이 생기면 처음 저장되고, 그때 주소가 `?id=…&edit=1`로 바뀝니다(쓰던 내용과 초점은 그대로).
- 저장하지 못하면 상태 줄이 오류 규칙(주홍 없음, 왼쪽 2px 줄)으로 이유를 말하고, 다시 보내서 나아질 수 있으면 `다시 시도`(연결 끊김은 같은 요청 키). 제목이 비었거나 저장된 할 일의 내용을 지우면 보내지 않고 그렇다고 말합니다.
- **적은 것을 잃지 않음**: 저장되지 않은 내용은 이 기기(`localStorage`)에 회사·사람·회의록별로 남기고(다른 사람에게는 보이지 않고, 로그아웃하면 지움), 다음에 열면 맨 위에 "이 기기에 저장하지 못한 내용이 남아 있습니다" + `이어서 쓰기` / `버리기`. 저장되지 않은 내용이 있는 채로 링크, 단축키(`g` …), 검색으로 옮기거나 창을 닫으면 먼저 묻습니다. 브라우저의 뒤로·앞으로는 Next 라우터가 `popstate`에서 바로 화면을 바꿔 막을 수 없으므로 묻지 않고, 대신 이 기기에 남긴 내용을 다시 열 때 이어서 쓰게 합니다(떠나기 전에 입력 칸을 벗어나면서 저장도 시작됨).
- **다른 사람이 먼저 고친 경우**(`409 conflict`): 저장을 멈추고 칸을 잠근 채 맨 위에 판을 엽니다. 제목 "다른 사람이 먼저 이 회의록을 고쳤습니다" + 내 내용은 그대로라는 한 줄 → `sunken` 상자에 최신 내용(제목, 날짜·참석자, 결정, 할 일, 노트) → 주 버튼 `내 내용으로 저장`, 보통 버튼 `최신 내용 불러오기`(버리기 전에 확인).
  내 내용으로 저장할 때 그사이 지워진 할 일은 새 할 일로 다시 만들고, 이슈와 이어진 할 일은 빠지지 않게 되살립니다.
- **지우기**: 작성자나 관리자에게만 `회의록 지우기`(보통 버튼)가 보입니다. 지우기 전에 확인하고, 이슈와 이어진 할 일이 있으면 연결이 사라진다고(이슈는 남음) 함께 말합니다. 지우면 목록으로 가고 알림 자리에 "… 회의록을 지웠습니다".

### GitHub 연결 (`/settings`, `/connect/github`)

- 연결 행: 고양이 표식 + Mono 로그인, `small` `ink-soft`로 "조직 · 모든 저장소 · 구성원 12명"(구성원 수는 조직이고 읽었을 때만), 오른쪽 끝 연결 날짜.
- 조직 설치 요청이 열려 있으면 카드 머리 아래 `sunken` 판(`rounded-control`) 하나. 첫 줄은 빈 고리 점(확인 중에는 `.busy-dot`) + "관리자에게 승인을 요청했습니다", 아래 `muted` "날짜 · 로그인 님이 요청", `ink-soft` 한 문장 안내. 관리자에게만 오른쪽에 32px 보조 버튼 `다시 확인`과 `요청 취소` 링크.
- `다시 확인` 결과는 판 안의 `role="status"` 줄: "아직 승인되지 않았습니다"(굵게 `ink`) · 할 일 한 문장. 승인된 조직이 여럿이면 조직마다 32px 보조 버튼(고양이 표식 + Mono 로그인)을 두고 고르게 합니다. 오류는 오류 규칙(왼쪽 2px 줄, 두 줄 + 오류 코드).
- 연결되면 판이 사라지고 그 자리에 잉크 점 + "연결되었습니다" + Mono 조직 로그인 한 줄, 목록에 새 행이 붙습니다.
- `/connect/github?setup_action=request`는 요청을 저장한 뒤 같은 판을 카드 안에 그리고, 이 화면의 주 동작이므로 `다시 확인`을 잉크색 주 버튼으로 둡니다. 연결되면 "연결되었습니다" 화면으로 바뀝니다.
- 상태 말은 이 세 가지로 고정합니다: "관리자에게 승인을 요청했습니다" / "아직 승인되지 않았습니다" / "연결되었습니다".

**연결 종류와 토큰 연결**

- 연결 행 로그인 옆에 종류 표지(`.tag`: 1px `rule-strong` 고리, `ink-soft` 글자, 주홍 아님) "GitHub 앱" 또는 "@로그인의 토큰"(저장된 토큰이 없으면 "토큰"). 카드 머리 아래 `small` `ink-soft` 한 줄 "개인 저장소는 GitHub 앱으로, 조직은 내 토큰으로 연결합니다."
- 행의 둘째 줄(`small`)에 "본문 저장 켜짐/꺼짐"(`storeBodies`, 읽기 전용)을 붙입니다. 토큰 연결이 하나라도 있으면 카드 아래에 굵은 "본문 저장" + 회사 정책 한 줄.
- 토큰 연결은 그 아래 건강 줄: 주의 표시(`연결 멈춤`, `곧 만료`) 또는 `동기화 쉬는 중` 표지 → Mono `••••a1b2` → 만료일("12월 17일 (목) 만료", 없으면 "만료일 없음"). 멈췄으면 할 일 한 줄, 관리자가 아니면 "관리자가 토큰을 바꾸면 다시 이어집니다."
- 관리자에게만 줄 아래 32px 보조 버튼: 멈춘 연결은 `토큰 바꾸기`가 먼저, 아니면 `가져올 것 고치기`(active 조직만) → `토큰 바꾸기` → `연결 끊기`. 끊기는 구성원 내보내기와 같은 모달(초점은 `그대로 두기`).
- 동기화 줄(1024px 이상은 상단 막대, 1023px 이하는 페이지 위 동기화 줄)에는 손볼 토큰만 나옵니다(곧 만료, 만료, 취소됨, 조직 접근 안 됨, 토큰 필요, 동기화 쉬는 중). 모든 토큰이 괜찮으면 토큰 자리에 아무것도 그리지 않습니다(빈 링크나 초점 가는 요소 없음).
  손볼 토큰이 있으면 가장 급한 하나를 설정으로 가는 링크로 둡니다: 주의 표시나 쉬는 중 표지 + 글자 + 손볼 토큰이 더 있으면 Mono `+N`. 글자는 1280px 이상에서 짧은 꼴 "@주인 · 12.17 만료"(멈춘 연결은 "토큰 필요 · 조직", 최대 160px, 넘치면 말줄임), 1023px 이하에서 "조직 · @주인의 토큰 · 만료일"(한 줄을 다 쓰고 넘치면 말줄임)입니다.
  1024~1279px 상단 막대에서는 토큰 링크에 표시와 `+N`만 두고 글자는 링크 `title`에 둡니다("3일 남음" 같은 덧말도 1024px 이상에서는 표시 옆에 쓰지 않고 1280px 이상의 짧은 꼴 글자에 맡김). 링크 `title`에는 손볼 토큰 모두의 긴 꼴을 둡니다. 1280px 이상이라도 막대가 "좁은 막대"이면(위 "틀" 규칙) 짧은 꼴 글자를 빼고 표시와 `+N`만 둡니다. 막대가 좁을 때의 검색창과 "마지막 동기화" 글자는 위 "틀"의 상단 막대 규칙을 따릅니다.
  괜찮은 토큰의 주인과 만료일은 설정의 연결 행에서 늘 보입니다.
- **토큰으로 조직 연결**(관리자만): 카드 머리의 보통 버튼이 카드 안에 3단계 판을 엽니다. 단계 표시는 Mono 번호 원(지금 단계 `ink` 바탕, 끝난 단계 체크) + 이름, `aria-current="step"`.
  1·2단계는 한 폼입니다(토큰과 조직을 한 요청으로 보내 토큰을 단계 사이에 들고 있지 않음): 토큰 칸은 "한 번만" 상자 안, 그 아래 fine-grained 권장, GitHub 토큰 만들기 링크(새 창), 켜야 할 권한 목록(Mono 이름 + 수준), 클래식 안내 → `@` 조직 로그인 칸 → 주 버튼 `토큰으로 연결하기`.
  3단계는 저장소 체크 목록(줄 전체가 `role="checkbox"`, 12개 넘으면 찾기 칸과 "N개 더 보기", 보관된 저장소는 뒤로), 팀 누름 칩(고르면 팀마다 프로젝트), 구성원(보드에 있음 / 없음, Mono 표지), 주 버튼 `저장소 N개 가져오기`. 결과는 같은 자리의 `role="status"` 묶음(고른 수, 만든 프로젝트, 만들지 않은 팀과 이유).
  판이 열려 있는 동안 `GitHub 연결하기`는 보통 버튼으로 물러섭니다(주 버튼 하나).
- **한 번만 상자**(`.secret`): `sunken` 바탕, 10px 모서리, 안쪽 16. 비밀 값(토큰, 초대 링크)을 넣거나 한 번 보여 줄 때 쓰고, 값은 Mono(`.secret-value`), 아래 `ink-soft` 한 줄로 "저장하면 다시 볼 수 없습니다"를 말합니다. 토큰은 `type="password"` 칸이고 화면 상태에 담지 않으며, 보내자마자(성공이든 실패든) 칸을 비웁니다. 저장 뒤에는 끝 네 글자(`••••abcd`)만 보입니다.
- 오류는 오류 규칙(주홍 없음, 왼쪽 2px 줄, 무엇이 문제인지 + 어떻게 하면 되는지 + 오류 코드)입니다. `token_scope_too_broad` / `token_scope_missing`은 끌 권한·빠진 권한을 Mono로, `sso_not_authorized`는 `ssoUrl`이 `https://github.com/…`일 때만 "GitHub에서 SSO 승인하기" 링크를 둡니다. `ghp_`, `github_pat_`로 시작하지 않는 값은 보내지 않고 같은 상자로 막습니다.

### 구성원 관리 (`/settings`, 관리자만)

- 설정의 GitHub 연결 카드 아래 `.card` 하나. 관리자가 아니면 그리지 않습니다.
- 맨 위 초대 줄: `GitHub 로그인` 입력(40px, 앞에 `@`, Mono) + 잉크색 `초대하기` 버튼. 390px에서는 두 줄로 쌓입니다. 아래 `muted` 한 줄로 "계정 번호로 바꿔 저장"을 알립니다.
- 초대가 만들어지면 그 아래 `sunken` 판에 링크(읽기 전용 입력, Mono `meta`)와 `링크 복사` 버튼, "지금 한 번만 보임 · 초대받은 계정만 · 7일" 한 줄. 링크는 다시 보여 줄 수 없으므로 목록에는 복사 대신 `새 링크 만들기`를 둡니다.
- 대기 중인 초대와 지금 구성원은 카드 안의 소제목(`small` 굵게 `ink-soft`) 아래 목록입니다. 줄 오른쪽에 32px 보조 버튼. 만료된 초대는 `ink-soft` 굵은 "만료됨"(주홍 아님).
- 관리자 표시는 1px `rule-strong` 고리 표지. 혼자 남은 관리자 자신의 `나가기`는 꺼 두고 그 이유를 줄 안에 `muted`로 씁니다.
- 줄 오른쪽 32px 보조 버튼은 `관리자로 지정`(구성원) 또는 `관리자 해제`(관리자)가 먼저, `내보내기`가 뒤입니다. 지정은 확인 없이 바로, 해제는 내보내기와 같은 모달로 확인합니다. 관리자가 한 명뿐이면 `관리자 해제`는 꺼 둡니다.
- 내보내기 확인은 모달(`<dialog>`): `surface`, 16px 모서리, `shadow-panel`, 뒤는 `--wb-scrim`. 초점은 안전한 `그대로 두기`에서 시작하고 Esc와 바깥 클릭은 취소입니다.

### 초대 링크 화면 (`/join#<token>`)

- 들어가기 전 화면(`GateFrame`) 틀. 로그인 전에는 "초대를 받았습니다" + GitHub 로그인 버튼(개발 모드는 로그인 이름 입력).
- 초대받은 계정이면 "OO에 합류" 제목, 초대한 사람 한 문장, 카드 안에 회사 표식·이름과 "<로그인> 계정으로 구성원이 됩니다", 유효 기간 한 줄, 48px `합류하기`.
- 다른 계정, 취소됨, 만료, 이미 씀, 잘린 링크는 "합류할 수 없습니다" 제목 + 오류 상자(무엇이 문제인지 / 어떻게 하면 되는지 두 줄). 다른 계정이면 `다른 계정으로 로그인` 버튼. 다른 계정에는 회사 이름을 보여 주지 않습니다.

### 단축키

| 키 | 동작 |
| --- | --- |
| `/` | 검색창으로 이동 (검색창 안에서 `Esc`는 빠져나오기) |
| `c` | 새 이슈 (이슈 패널의 만들기 모드) |
| `a` | 이슈 패널이 열려 있으면 그 이슈의 담당자 바꾸기. 패널이 닫힌 주기 계획 화면에서는 고른 일(없으면 초점이 있는 대기 목록 줄)을 이번 주기(없으면 다음 주기)에 넣기 |
| `x` | 주기 계획 화면에서 초점이 있는 대기 목록 줄을 고르거나 풀기 |
| `s` 다음 `1`~`5` | 초점이 있는 카드(없으면 열린 이슈 패널의 이슈)의 상태를 할 일 / 진행 중 / 리뷰 중 / 완료 / 취소로. `s`를 누르면 화면 위쪽 가운데에 번호 안내가 2초 동안 나옵니다 |
| `g` 다음 `o` `m` `p` `b` `c` `n` `s` | 개요, 내 작업, 사람별 보드, 프로젝트별 보드, 주기 계획, 회의록, 설정 |
| `j` / `k` | 목록·표·보드에서 다음 / 이전 줄로 초점 이동(`data-row`가 붙은 요소) |
| `Enter` | 초점이 있는 줄 열기 |
| `Esc` | 이슈 패널 닫기 |

- 글자 키는 키 위치(`KeyboardEvent.code`: `KeyG`, `KeyJ`, `KeyO` 등)로 판정합니다. 한글 입력 상태에서도 같은 자리의 키로 동작합니다. `/`는 `key` 또는 `Slash`로 판정합니다.
- 입력창, 선택 상자에 글자를 넣는 중이거나, 한글 조합 중이거나, Ctrl·Cmd·Alt·Shift를 누른 채면 동작하지 않습니다.
- `j`/`k`는 옮겨 갈 줄이 있을 때만 키 입력을 가로챕니다. 이슈 패널이 열려 있는 동안 `/`, `c`, `g`, `j`, `k`는 꺼지고 `s`는 패널의 이슈에 씁니다.
- `s`는 바꿀 카드가 있을 때만 가로챕니다. `g` 바로 다음의 `s`는 설정 화면으로 가는 키입니다.
- 이슈 패널이 열려 있으면 `a`가 담당자 목록을 엽니다(입력 중에는 동작하지 않음). 패널이 열린 동안 주기 계획의 `a`, `x`는 꺼집니다.
  그래서 `a`는 언제나 하나의 뜻만 갖습니다: 패널 안에서는 담당자, 패널 밖 주기 계획에서는 주기에 넣기. 다른 화면에서 패널 없이 누른 `a`는 아무것도 하지 않습니다.
- `g c`는 주기를 꺼 둔 회사에서도 주기 계획 화면으로 가고, 그 화면이 꺼져 있다고 말합니다. 메뉴 항목은 주기를 켠 경우에만 보입니다.
- 새 이슈 폼 안에서는 `Ctrl`+`Enter`(맥은 `⌘`+`Enter`)가 `이슈 만들기`입니다.
- 화면에 보여 주는 단축키(`kbd`)는 모두 실제로 동작해야 합니다. 새 목록을 만들면 줄에 `data-row`를 붙입니다.

### 빈 화면, 들어가기 전 화면, 오류

- **빈 화면**: 한 문장으로 사실을 말하고, 좋은 소식이면 그렇다고 말합니다. `muted` 글자 + `rule-strong` 점선 상자(10px 모서리).
  보드의 빈 열은 상자 없이 `muted` "없음" 한 줄.
- **들어가기 전 화면**(`/login`, 확인 중, 회사 없음, 회사 선택, 세션 만료, 오류, 로그인 마무리, 개발 모드 선택): 틀 없는 단독 화면(`GateFrame`).
  - `canvas` 바탕 전체. 왼쪽 위에 `wb` 표식(28px) + "업무 보드", 오른쪽 위에 언어·밝기 토글, 맨 아래 `muted` `meta` 표어 한 줄. 검색, 단축키, 메뉴는 없습니다.
  - 가운데 440px 기둥을 세로 가운데에: 짧은 선 + `small` 머리(로그인, 회사 확인, 연결 등) → `display` 제목 → `body` 한 문장 → 16px 모서리 카드 하나(안쪽 24px).
  - 카드 안 주 동작은 48px 잉크색 버튼 하나(폭 전체).
  - `/login`은 1024px 이상에서 두 칸이고, 오른쪽 `sunken` 판에 한 문장 현황 미리 보기를 둡니다. 미리 보기는 오른쪽 위 `예시` / `Example` 표지와 아래 "예시 데이터입니다" 한 줄로 실제 데이터가 아님을 밝힙니다. 1023px 이하에서는 그리지 않습니다.
  - 회사 없음, 회사 선택 화면은 카드 아래에 `small` `muted` 한 줄 "<로그인> 계정으로 로그인함 · 로그아웃".
  - 화면이 바뀌면 초점이 제목(`h1`, `tabIndex=-1`)으로 갑니다. 화면마다 `<main>`과 `h1`은 하나입니다.
  - 세션이 끝나 돌아왔으면 로그인 카드 맨 위에 안내(`Notice`)를 둡니다. 네트워크·서버 오류는 로그아웃으로 보지 않고 "다시 시도" 화면을 보여 줍니다.
- **개발 모드**(Supabase 설정 없음): 같은 틀의 `/login` 카드에서 개발용 사용자를 고르고(48px 선택 상자), 실행 방법은 카드 안에 접어 둡니다.
  "업무 보드" 옆에 "개발 모드" 표지(1px `rule-strong` 고리)를 둡니다.
- **오류**: 주홍을 쓰지 않습니다. `ink` 글자 + 왼쪽 2px `ink-soft` 줄 + 해결 방법 한 줄.
- **불러오는 중**: 회색 빈 줄(skeleton) 대신 카드 머리는 바로 그리고 내용 자리에 `muted` "불러오는 중…".

### 말

- 지라 용어 금지: Epic → 큰 목표, Task → 작업, Backlog → 대기 목록, Sprint → 주기, Story point → 크기.
- GitHub 말: Personal access token → 토큰(입력 칸 이름만 "개인 액세스 토큰"), token owner → 토큰 주인, Installation → 설치, GitHub App → GitHub 앱. 권한 이름(`Issues`, `read:org`)은 GitHub 화면과 같게 영어 Mono로 둡니다.
- 버튼은 동사로 끝냅니다: "이슈로 만들기", "보드에서 보기".
- 숫자 뒤에 단위: "3건", "12일째", "2일 전".

### 언어

- 화면 언어는 한국어(`ko`)와 영어(`en`) 두 가지입니다. 고른 값은 `localStorage`의 `workboard.lang`에 두고, 처음 오면
  브라우저 언어가 `ko`로 시작할 때 한국어, 아니면 영어입니다. 고른 언어는 `<html lang>`에 들어가고, 줄 간격도 이 값을 따릅니다.
- 화면 문구는 모두 `web/src/lib/i18n/ko.ts`(원본)와 `en.ts`에 둡니다. 컴포넌트에 문구를 직접 쓰지 않고 `useT()`로
  꺼내 쓰며, 날짜·경과·숫자는 `useFormat()`(`Intl`)으로 만듭니다. 한쪽에만 있는 키는 `tsc`가 막습니다.
- 사용자가 쓴 내용(이슈 제목, 댓글, 회의록, 저장소·사람 이름)은 번역하지 않습니다.
- 영어도 지라 용어를 피합니다: Epic → Goal, Sprint → Cycle, Story point → Size. 상태는 To do / In progress /
  In review / Done / Canceled. 짧고 담백한 개발 도구 말투로, 셀 수 있는 말은 단수·복수를 맞춥니다("1 issue", "3 issues").
- 좁은 칸(손봐야 할 일의 경과, 최근 흐름의 시각)은 영어에서 짧은 꼴("3d ago")을 씁니다.

## 7. 토큰

값은 `web/src/app/globals.css`에 있고, 이 문서 2~4장의 표와 같아야 합니다. Tailwind 4의 `@theme inline`으로 연결해
`bg-canvas`, `bg-surface`, `text-ink`, `text-faint`, `bg-on-ink`, `border-rule`, `bg-hover`, `bg-status-review`, `text-accent`, `font-mono`,
`text-display` … `text-meta`, `text-figure`, `rounded-control` / `rounded-item` / `rounded-card` / `rounded-sheet`, `shadow-elev-1`, `shadow-elev-2`,
`shadow-panel`, `ease-tool` 같은 클래스가 생깁니다.

- 줄 간격은 `--lh-*` 변수에 있고 `:root[lang="en"]`과 639px 이하에서 바뀝니다. `text-*` 클래스가 이 변수를 씁니다.
- 다크 값은 `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`와 `:root[data-theme="dark"]` 두 곳에 같게 둡니다.
  기본은 OS 설정을 따르고, 밝게·어둡게 토글이 `<html data-theme>`를 고정하면 그쪽이 우선합니다.
- 이슈 패널 뒤 어둑한 막은 `--wb-scrim`(라이트 `rgb(14 16 19 / 0.32)`, 다크 `rgb(0 0 0 / 0.55)`)입니다.
- 공용 클래스: `.card`(판), `.btn` / `.btn-primary` / `.btn-lg`(버튼), `.seg`(두 칸 토글), `.flag` / `.flag-fill`(주의), `.tag`(주홍 없는 표지: 연결 종류, 동기화 쉬는 중), `.secret` / `.secret-value`(한 번만 상자), `.gutter`(왼쪽 주홍 거터),
  `.kbd`(단축키), `.bar`(막대), `.link`, `.tabs`(스스로 스크롤하는 탭 줄), `.reveal`,
  `.prop-trigger` / `.menu`(패널에서 고치는 값과 그 목록) / `.menu-wide` / `.menu-foot`(여러 값을 골라 저장하는 목록과 그 아래 줄), `.pick-box`(여러 개를 고르는 체크 상자: 담당자 목록, 대기 목록 줄), `.busy-dot`(기다리는 중), `.drop-col` / `.card-lifted`(끌어 옮기기), `.notice` / `.undo-clock`(변경 알림과 되돌리기 남은 시간),
  `.spark` / `.spark-line` / `.spark-ideal` / `.spark-base` / `.spark-dot`(남은 일 추이, 점 고리 색은 `--spark-bg`), `.cols`(한 주에 끝낸 일 기둥).
- 상태 색은 코드에서 한 곳(`web/src/lib/labels.ts`의 `STATUS_DOT`)에서만 클래스 이름으로 연결합니다.

## 8. 화면을 만들 때 확인할 것 (PR 체크리스트)

PR 설명에 아래 항목을 복사해 확인 표시합니다.

- [ ] 새 화면을 만들기 전에, 기존 화면이나 이슈 패널에 붙일 수 없는지 먼저 따졌다(흩어지면 아무도 안 봄).
- [ ] 화면 맨 위가 "이 화면에서 가장 중요한 사실 하나"를 말한다.
- [ ] 색은 토큰만 썼다. `slate-*`, `blue-*` 같은 Tailwind 기본 색이나 16진수 값을 직접 쓰지 않았다.
- [ ] 글자 크기는 2장의 단계(`text-display` … `text-meta`)에서만 골랐다. `text-[12.5px]` 같은 임의 크기가 없다.
- [ ] Mono는 ASCII(번호, 숫자, 단축키)에만 썼다. 날짜·경과·한글은 Sans다.
- [ ] 주홍(`accent`)은 주의 표시에만 썼고, 한 화면에 칠해진 면이 3곳 이하다. 주 버튼은 잉크색 하나다.
- [ ] 상태는 점 + 이름으로 보이고, 이름이 할 일 / 진행 중 / 리뷰 중 / 완료 / 취소(영어 To do / In progress / In review / Done / Canceled) 중 하나다.
- [ ] 새 문구는 `ko.ts`와 `en.ts`에 함께 넣었고, 영어로 바꿔도 넘치거나 줄이 깨지지 않는다.
- [ ] 지라 용어가 없다. 고급 필드(주기, 크기, 우선순위)는 설정에서 켠 경우에만 보인다.
- [ ] 이슈가 보이는 모든 곳은 클릭하면 이슈 패널(`?issue=`)이 열린다. 목록 줄에는 `data-row`가 있어 `j`/`k`로 갈 수 있다.
- [ ] 화면에 보여 준 단축키는 모두 동작하고, 입력 중에는 동작하지 않는다.
- [ ] 빈 상태, 불러오는 중, 오류 문구를 모두 넣었다.
- [ ] 라이트와 다크, 한국어와 영어 모두에서 확인했다.
- [ ] 390 / 768 / 1280px에서 5장 규칙대로 바뀌고, 390px에서 페이지 가로 스크롤이 없다(탭 줄만 스크롤).
- [ ] 키보드로 모든 클릭 대상에 갈 수 있고 초점 테두리가 보인다.
- [ ] 움직임은 4장 규칙 안이고 `prefers-reduced-motion`에서 꺼진다.
